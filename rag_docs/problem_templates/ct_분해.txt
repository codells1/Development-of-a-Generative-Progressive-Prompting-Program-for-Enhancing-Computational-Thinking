CT 요소: 분해 (Decomposition)
problem_index: 0
난이도: 매우쉬움
형식: 비코드 (문제상황 기반)

== 개요 ==
코드가 아니라 실생활 문제상황을 입력·처리·출력 또는 독립적인 하위 작업으로 나누고,
어떤 부분이 어느 단계인지 / 몇 단계인지 / 어떻게 묶이는지를 파악하는 능력을 측정한다.
화면에 코드는 등장하지 않으며, 글(또는 그림)로 된 상황 설명만 제시한다.
'왜 그 일을 하는가'(전체 목적·의미)는 통합에서 다루고, 여기서는 '작업을 어떻게 쪼개는가'(구조 분할)만 묻는다.

== 질문 패턴 ==
(각도: 상황을 단계·하위작업으로 분할. 전체 목적·의미는 묻지 않는다.)
- 다음 작업을 (준비/처리/마무리 등)으로 나누면 몇 단계인가?
- {상황}에서 '{특정 행동}'은 어느 단계에 해당하는가?
- 이 일을 독립적으로 처리할 수 있는 하위 작업으로 나눈 것으로 가장 적절한 것은?
- 다음을 두 묶음으로 나눈다면 어떻게 묶는 것이 맞는가?
- {목표}를 이루기 위해 한 단계로 묶어도 되는(또는 반드시 나눠야 하는) 것은?

== 인지 조작 ==
복잡한 상황 전체를 한 덩어리로 보지 않고, 독립적으로 수행 가능한 하위 작업 단위로 분리한다.
각 단위의 경계(어디서 한 작업이 끝나고 다음이 시작되는지)를 판단하고, 서로 겹치지 않게 나눈다.

== 오답 설계 원칙 ==
- 서로 다른 두 작업을 하나로 합쳐 단계 수를 줄인 오답 제시
- 단계 수를 1개 틀리게 제시 (3단계 → 2단계 또는 4단계)
- 한 작업을 불필요하게 둘로 쪼갠 오답 제시
- 순서상 뒤에 와야 할 작업을 앞 단계로 잘못 배치한 오답 제시
- 하위 작업이 아니라 '전체 목적'을 한 단계처럼 끼워 넣은 오답 제시

== 난이도 기준 ==
- 일상에서 누구나 아는 작업(요리, 등교 준비, 빌리기, 주문 처리 등) 사용
- 하위 작업 2~4개로 경계가 비교적 뚜렷한 상황
- 전문 지식 없이 상식으로 단계가 보이는 상황

== 예시 문제 1 ==
상황:
  온라인 쇼핑몰에서 주문이 들어오면 다음 일이 차례로 일어난다.
  ① 손님이 장바구니에 담은 상품을 확인한다
  ② 결제가 정상인지 검사한다
  ③ 창고에서 상품을 포장한다
  ④ 택배로 보낸다

Q: 이 과정을 '주문 확인 / 상품 처리'의 두 묶음으로 나눈다면 가장 적절한 것은?
A. (①) / (②③④)
B. (①②) / (③④)  (정답)
C. (①②③) / (④)
D. (①) / (②) / (③) / (④)
정답: B
해설: ①②는 들어온 주문이 올바른지 확인하는 일(주문 확인), ③④는 실제 상품을 준비해 보내는 일(상품 처리)이다. 결제 검사(②)는 아직 상품을 만지지 않으므로 확인 묶음에 들어간다.

== 예시 문제 2 ==
상황:
  카페에서 아메리카노 한 잔을 만드는 과정이다.
  원두를 갈기 → 뜨거운 물 준비하기 → 에스프레소 내리기 → 물과 섞기 → 잔에 담아 내기

Q: 위 과정을 '재료 준비 / 추출 / 완성'의 기능 단계로 나눌 때, '재료 준비'에 해당하는 것을 모두 고르면?
A. 원두를 갈기
B. 원두를 갈기, 뜨거운 물 준비하기  (정답)
C. 에스프레소 내리기
D. 물과 섞기, 잔에 담아 내기
정답: B
해설: 원두를 갈고 물을 준비하는 두 가지가 추출 전 재료를 갖추는 '재료 준비'다. 에스프레소를 내리는 것은 추출, 섞어 잔에 담는 것은 완성 단계다.
