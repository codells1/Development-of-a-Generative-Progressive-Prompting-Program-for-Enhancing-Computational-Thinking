# 학습 단계 평가 결과 — 구현 사양

세션이 끝나면 **학생 발화**를 근거로 **4개 컴퓨팅 사고력 요소**를 상/중/하로 평정하고, **학생용 서술 피드백**을 생성해 결과 화면에 표시한다.

## 변경 요점 (이번 버전)
- **4개 요소로 축소.** 기존 용어사용·자료표현·동작파악 제거.
  - 용어사용 → 추상화 상(우수) 수준에 포함 (이중 채점 제거)
  - 자료표현 → 퀴즈 변수추적 문항으로 이동 (대화 로그 측정 한계)
  - 동작파악 → 실행흐름 상(우수) 수준에 포함 (동일 인지 과정)
- **CT 총점 포함:** 문제분해·추상화·실행흐름 3개 (최대 9점).
- **자기해결:** SRL 지표로 별도 기록. CT 총점 미포함.
- **NA 표기 없음:** 관련 발화가 없는 요소는 elements 배열에서 아예 제외. "NA" 값 사용 안 함.
- 학생 화면에 **숫자 총점 미표시** 유지.
- 왼쪽 **서술 피드백**은 박스 규격에 맞춰 길이 제한 유지.

---

## 1. 출력 (2가지)
- **요소별 상중하** (측정된 요소만): 화면 **오른쪽** 배지로 표시 + 내부 기록.
- **서술형 피드백** (한 단락): 화면 **왼쪽**에 표시.
- 숫자 점수(총점)는 **만들지도, 보여주지도 않는다.**

---

## 2. 평가 루브릭 (4요소)

- grades: 상=3 · 중=2 · 하=1 (표시는 상/중/하, 내부값 3/2/1).
- 관련 발화가 없는 요소는 elements 배열에서 **아예 제외**한다. "NA" 표기 없음.
- 단, '결과·정답만 요구'처럼 명백히 회피적 발화가 있으면 하로 평정한다.
- 단위: 학생 발화(질문·요청·진술). 세션 전반의 전형(최빈) 수준으로. 단발 1회 발화는 근거 불가.
- 중→상 경계: 표면 묘사=중, 목적·이유·구조 통합=상.
- 요소 순서(=화면 표시 순서): 문제분해, 추상화, 실행흐름, 자기해결.
- CT 총점: 문제분해+추상화+실행흐름 합산 (측정된 요소만). 자기해결은 별도 기록.

| 요소 | 하 | 중 | 상 |
|---|---|---|---|
| 문제분해 | 안 나누고 통째로 요청 | 둘 이상으로 나누나 부분 간 순서·연결 없음 | 분해 + 부분 간 관계·처리 순서까지 짚음 |
| 추상화 ★ | 모든 부분을 동등하게 취급 (표면적 실행 나열) | 핵심만 지목하나 보조 구분 못 함 (한 줄씩 서술) | 핵심·보조 대비 + 전체 목적을 한 문장으로 요약 |
| 실행흐름 | 절차에 무관심, 결과만 요청 | 순서를 한 줄씩/대략 자연어로 서술 | 순차·선택·반복 구조를 명시 |
| 자기해결 | 직접적인 정답만 요구 | 힌트 후 다시 정답 요청으로 회귀 | 힌트로 자기 접근·다음 단계 제안 |

> **추상화(★) 중↔상 분기점:** 한 줄씩 나열=중 / 전체 목적 한 문장=상.
> (Chen et al., 2020 EiPE Multistructural↔Relational 전환)

---

## 3. 서술형 피드백 생성 규칙

- 길이: 4~6문장, 공백 포함 150~220자 이내(박스 규격). 넘치거나 비지 않게 상한 강제.
- 구조: ① 격려 도입 1문장 → ② 잘한 점(상/중 1~2개, 구체적 발화 근거) → ③ 다음에 해볼 점(하/중 1~2개, "다음엔 ~해보자").
- 과제 중심(능력·서열 칭찬 금지). 글에 상/중/하 라벨·숫자·정답을 쓰지 않는다(소크라테스식: 무엇을 살펴볼지만).
- 약점은 한 번에 최대 1~2개. 발화가 없어 제외된 요소는 약점으로 지적하지 않는다(권유는 가능).
- 자기해결이 하여도 약점으로 직접 지적하지 않는다.
- 톤: 중·고생 눈높이의 친근하고 격려적인 2인칭, 존댓말, 성장 중심.
- 엣지: 전부 하면 과제 관련 노력을 짚고 다음 단계 하나만. 전부 상이면 한 단계 깊은 도전 제안.

---

## 4. 출력 JSON 스키마

관련 발화가 있는 요소만 elements 배열에 포함한다. 발화가 없는 요소는 객체 자체를 생략한다.

```json
{
  "elements": [
    {"id": "decomposition",   "name": "문제분해", "grade": "중"},
    {"id": "abstraction",     "name": "추상화",   "grade": "하"},
    {"id": "control_flow",    "name": "실행흐름", "grade": "상"},
    {"id": "self_resolution", "name": "자기해결", "grade": "중", "srl": true}
  ],
  "narrative_feedback": "왼쪽 패널에 표시할 한 단락"
}
```

- `grade` ∈ `"상" | "중" | "하"`. **"NA" 사용 안 함.**
- 발화가 없는 요소는 배열에서 생략 — 프론트엔드는 4개 고정이 아닌 **가변 배열**로 처리해야 함.
- `srl: true` 표시 요소(자기해결)는 CT 총점 집계에서 제외하고 별도 기록.
- CT 총점 계산 (내부용): elements 중 srl이 없는 요소의 grade 합산 (최대 9점). UI에 미표시.

---

## 5. 결과 화면 표시 규칙 (UI)

- **왼쪽 패널**: 제목("컴퓨팅 사고력") + `narrative_feedback`만. 숫자 점수 표시 안 함.
- **오른쪽 패널**: 제목 "루브릭 지표별 결과" 한 섹션. elements 배열에 포함된 요소만 순서대로 표시, 각 옆에 상/중/하 배지.
  - 문제분해 / 추상화 ★ / 실행흐름 → CT 지표 (일반 배지)
  - 자기해결 → 별도 표시 (배지 옆 작은 'SRL' 태그 또는 회색 계열)
  - **발화가 없어 제외된 요소는 화면에 표시하지 않는다.** (기존 "—" 처리 제거)
- 배지 색: 단계 구분용 중립 색. '하'를 강한 빨강 경고로 쓰지 않음(위축 방지). 강조는 왼쪽 서술 피드백이 담당.

---

*설계 메모:*
*- NA 표기를 제거하고 해당 요소를 아예 제외하는 것은, "N/A"가 학생에게 "측정 실패"처럼 보일 수 있어 불필요한 혼란을 방지하기 위함이다. 측정된 요소만 배지로 표시하면 충분하다.*
*- 4개 지표 축소의 이론적 근거: 용어사용은 추상화 상(우수)에 자연 포함(Cross-contamination 제거), 동작파악은 실행흐름 상(우수)에 포함(Block Model 동일 인지 차원), 자료표현은 퀴즈 변수추적 문항으로 분리 측정(평가 공학적 분리). (Chen et al., 2020; Schulte, 2008)*
