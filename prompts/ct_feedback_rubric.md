# 학습 단계 평가 결과 — 구현 사양

세션이 끝나면 **학생 발화**를 근거로 **7개 컴퓨팅 사고력 요소**를 상/중/하로 평정하고, **학생용 서술 피드백**을 생성해 결과 화면에 표시한다.

## 변경 요점 (이번 버전)
- 7개 요소를 **하나의 그룹**으로 본다. (자기 해결을 '메타인지'로 분리하지 않음.)
- **패턴 인식 항목 삭제.**
- 학생 화면에 **숫자 총점 미표시** (기존 "61점" 제거).
- 왼쪽 **서술 피드백**은 박스 규격에 맞춰 길이 제한.

---

## 1. 출력 (2가지)
- **요소별 상중하** (7개): 화면 **오른쪽** 배지로 표시 + 내부 기록.
- **서술형 피드백** (한 단락): 화면 **왼쪽**에 표시.
- 숫자 점수(총점)는 **만들지도, 보여주지도 않는다.**

---

## 2. 평가 루브릭 (7요소)

- grades: 상=3 · 중=2 · 하=1 (표시는 상/중/하, 내부값 3/2/1). 관련 발화 없으면 NA(집계 제외, 회피적 발화는 하).
- 단위: 학생 발화(질문·요청·진술). 세션 전반의 전형(최빈) 수준으로. 중→상 경계: 표면 묘사=중, 목적·이유·구조 통합=상.
- 요소 순서(=화면 표시 순서): 문제 분해, 용어 사용, 추상화, 실행 흐름, 자료 표현, 동작 파악, 자기 해결.

| 요소 | 하 | 중 | 상 |
|---|---|---|---|
| 문제 분해 | 안 나누고 통째로 요청 | 둘 이상으로 나누나 부분 간 순서·연결 없음 | 분해 + 부분 간 관계·처리 순서까지 짚음 |
| 용어 사용 | 일상어만, 프로그래밍 용어 미사용 | 용어를 쓰나 1회 이상 오용·혼동 | 사용한 용어가 모두 정확 |
| 추상화 | 모든 부분을 동등하게 취급 | 핵심만 지목(보조 구분 못 함) | 핵심·보조를 대비 + 핵심에 초점 |
| 실행 흐름 | 절차에 무관심, 결과만 요청 | 순서를 한 줄씩/대략 자연어로 서술 | 순차·선택·반복 구조를 명시 |
| 자료 표현 | 데이터 언급 없이 결과만 | 형태를 일상적으로 언급(숫자·글자) | 타입·자료구조를 명시 |
| 동작 파악 | 동작 안 묻고 그대로 수용 | 실행 결과·출력만 질문 | 왜·어떻게(원리·인과)를 질문 |
| 자기 해결 | 직접적인 정답만 요구 | 힌트 후 다시 정답 요청으로 회귀 | 힌트로 자기 접근·다음 단계 제안 |

---

## 3. 서술형 피드백 생성 규칙

- 길이: 4~6문장, 공백 포함 150~220자 이내(박스 규격). 넘치거나 비지 않게 상한 강제.
- 구조: ① 격려 도입 1문장 → ② 잘한 점(상/중 1~2개, 구체적 발화 근거) → ③ 다음에 해볼 점(하/중 1~2개, "다음엔 ~해보자").
- 과제 중심(능력·서열 칭찬 금지). 글에 상/중/하 라벨·숫자·정답을 쓰지 않는다(소크라테스식: 무엇을 살펴볼지만).
- 약점은 한 번에 최대 1~2개. NA(안 다룬) 요소는 약점으로 지적하지 않음(권유는 가능).
- 톤: 중·고생 눈높이의 친근하고 격려적인 2인칭, 존댓말, 성장 중심.
- 엣지: 전부 하/NA면 과제 관련 노력을 짚고 다음 단계 하나만. 전부 상이면 한 단계 깊은 도전 제안.

---

## 4. 출력 JSON 스키마

```json
{
  "elements": [
    {"id": "decomposition",          "name": "문제 분해", "grade": "중"},
    {"id": "terminology",            "name": "용어 사용", "grade": "중"},
    {"id": "abstraction",            "name": "추상화",   "grade": "하"},
    {"id": "control_flow",           "name": "실행 흐름", "grade": "상"},
    {"id": "data_representation",    "name": "자료 표현", "grade": "하"},
    {"id": "behavior_comprehension", "name": "동작 파악", "grade": "중"},
    {"id": "self_resolution",        "name": "자기 해결", "grade": "중"}
  ],
  "narrative_feedback": "왼쪽 패널에 표시할 한 단락"
}
```
- `grade` ∈ `"상" | "중" | "하" | "NA"`. 숫자 총점 필드 없음. `elements` 순서 = 화면 표시 순서, 7개 고정.

---

## 5. 결과 화면 표시 규칙 (UI)

- **왼쪽 패널**: 제목("컴퓨팅 사고력") + `narrative_feedback`만. 숫자 점수 표시 안 함(기존 "61점" 원형 배지 제거, 레이아웃 유지).
- **오른쪽 패널**: 제목 "루브릭 지표별 점수" 한 섹션에 7개 요소를 순서대로 나열, 각 옆에 상/중/하 배지. '메타인지' 별도 섹션·'패턴 인식' 항목 없음.
- **NA 처리**: 'N/A'를 오류·결핍처럼 강조하지 말 것. 회색 "—"·흐린 처리로 둔다.
- 배지 색: 단계 구분용 중립 색. '하'를 강한 빨강 경고로 쓰지 않음(위축 방지). 강조는 왼쪽 서술 피드백이 담당.

---

*설계 메모: 학생 화면에서 숫자 총점을 빼고 서술 중심으로 두는 것은, 점수를 함께 보여주면 학생이 서술을 읽지 않고 점수에만 집중하기 쉽기 때문이다. 서술은 "다음에 무엇을 해볼지(피드포워드)"를 과제 중심으로 담는다.*
