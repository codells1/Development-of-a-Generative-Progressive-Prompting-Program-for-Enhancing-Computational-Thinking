# 컴퓨팅 사고력 평가 루브릭

학생이 **주어진 파이썬 코드를 읽으며 챗봇과 나눈 대화**에서, **학생의 발화(질문·요청·진술)**를 근거로 컴퓨팅 사고력을 평정한다. 각 지표를 **미흡(1점)·보통(2점)·우수(3점)**로 매긴다.

## 채점 규칙

1. **채점 단위** — 학생 발화. '이해했는지'가 아니라 발화로 드러난 것만 채점한다.
   *근거(연구·방법론): SOLO는 본래 '관측된 산출물(Observed)' 기반 평정이고, 분석적 루브릭은 관측 가능한 수행기술로 기술한다. 또 대화 로그만으로는 '이해'를 직접 관측할 수 없다. (설문의 '너무 정성적·측정 모호' 지적 반영.)*
2. **세션 평정** — 세션 전반에서 전형적으로 나타난 수준으로 매긴다. 단발성 1회 발화는 근거로 삼지 않는다.
   *근거(설계 판단): 운 좋은 단발 우수 발화로 점수가 부풀지 않도록 '전형(다수) 수행' 관점을 택함. '도달 최고 수준'으로 잡는 대안도 동등하게 가능하며, 어느 쪽이든 일관 적용하면 된다.*
3. **복합 조건** — 한 칸에 조건이 둘이면 둘 다 충족할 때 그 점수, 하나만이면 한 단계 아래.
   *근거(방법론): 자료 표현 3점('타입+이유') 등 조건이 둘 묶인(double-barreled) 칸의 부분 충족 모호성을 없애기 위한 표준 처리.*
4. **부재 처리** — 한 지표 관련 발화가 세션에 전혀 없으면 **N/A**(평균에서 제외). 단, '결과·정답만 요구'처럼 회피적 발화가 있으면 1점.
   *근거(연구): 김재경(2017)이 무응답·산출물 없음을 1~3점과 분리해 처리한 것을 응용. '측정 기회가 없던 것'과 '못하는 것'을 구분(타당도).*
5. **귀속** — 한 발화가 여러 지표에 걸리면 그 발화의 **초점**으로 귀속한다.
   *근거(연구·방법론): "한 평가 기준이 둘 이상의 CT 개념을 표현"하는 지표 중복(판별타당도) 문제 대응. 각 지표가 어떤 인지 과정을 재는지 분리·명시하라는 권고(Oser 등, 2025).*
6. **보통↔우수 일반 원칙** — "한 줄씩/표면 묘사"면 2점, "목적·이유·구조를 통합"하면 3점.
   *근거(연구): 코드 이해의 SOLO 분류(Lister 등, 2006). 다중구조=한 줄씩 설명하되 목적 못 댐, 관계=세부 참조 없이 목적 설명. 학생 절반이 다중구조에 머문다는 결과가 반복되는, 이 분야의 핵심 임계. (설문의 '보통/우수 모호' 지적 반영.)*
7. **천장 주의** — 실행 흐름 등 일부 지표의 3점은 해당 코드에 그 구조가 있어야 도달 가능하므로, 문제 설계 시 우수 도달이 가능하도록 코드를 구성한다.
   *근거(설계 판단·공정성): 문제마다 도달 가능한 최고점이 달라지는 천장 효과를 보정하기 위함.*

## ① 문제 분해
*측정 축: 과제를 하위 단위로 나누고 부분 간 관계·순서를 다루는가*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 나누지 않고 전체를 한 번에 해결 요청 | "이 코드 어떻게 동작하는지 통째로 다 설명해 주세요." |
| 2점 | 둘 이상으로 나눠 질문하나 부분 간 순서·연결은 없음 | "이 함수는 뭐예요? 그리고 이 반복문은요?" |
| 3점 | 분해 + 부분 간 관계·처리 순서까지 짚어 질문 | "입력을 리스트로 바꾸고 그다음 반복문에서 최댓값을 찾는 순서죠? 두 부분이 어떻게 이어져요?" |

## ② 용어 사용
*측정 축: 사용한 프로그래밍 용어가 정확한가(오용 횟수 기준)*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 일상어만, 프로그래밍 용어 거의 미사용 | "이 칸에 숫자를 넣는 거예요?" |
| 2점 | 용어를 쓰나 1회 이상 오용·혼동(예: 변수↔함수) | "이 함수가… 아니 변수가 더하는 거 맞죠?" |
| 3점 | 사용한 용어가 모두 정확(오용 0) | "이 매개변수로 받은 리스트를 반복문으로 순회해 반환값에 누적하죠?" |

## ③ 추상화
*측정 축: 핵심(본질)과 보조(부수)를 함께 구분하는가*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 중요도 구분 없이 모든 부분을 동등하게 취급 | "한 줄 한 줄 다 똑같이 설명해 주세요." |
| 2점 | 핵심만 지목(보조는 언급 안 함) | "여기 최댓값 찾는 부분이 제일 중요한 것 같아요." |
| 3점 | 핵심과 보조를 대비해 명시하고 핵심에 초점 | "최댓값 찾는 반복문이 핵심이고 print로 꾸미는 건 부수적이죠? 핵심만 볼게요." |

## ④ 실행 흐름
*측정 축: 처리 순서와 제어구조(순차·선택·반복)를 다루는가*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 절차에 무관심, 결과·정답만 요청 | "결과만 알려 주세요." |
| 2점 | 순서를 한 줄씩/대략 자연어로 서술 | "위에서부터 한 줄씩 실행되는 거 맞죠?" |
| 3점 | 순차·선택·반복 중 어떤 구조로 흐르는지 명시 | "for문이 길이만큼 돌고, 안의 if가 참일 때만 카운트가 오르는 순서 맞죠?" |

## ⑤ 자료 표현
*측정 축: 데이터의 타입·자료구조를 다루는가 (이유 설명은 가산 신호)*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 입출력 데이터 언급 없이 결과만 요청 | "결과만 보여 주세요." |
| 2점 | 데이터 형태를 일상적 수준으로 언급 | "여기 숫자가 들어가요." / "글자 목록 같은데요." |
| 3점 | 타입·자료구조를 명시(이유까지 설명하면 더 분명한 우수) | "정수 리스트라 인덱스로 접근하죠?" |

## ⑥ 동작 파악
*측정 축: 무엇(결과)이 아니라 왜·어떻게(원리·인과)를 묻는가*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 동작을 묻지 않고 코드를 그대로 받아들임 | "그냥 이대로 쓰면 되는 거죠?" |
| 2점 | 실행 결과·출력(무엇이 일어나는지)만 질문 | "이거 실행하면 뭐가 나와요?" |
| 3점 | 왜 필요한지·어떻게 그 결과가 나오는지(원리·인과) 질문 | "max를 0으로 시작하면 왜 음수일 때 틀려요?" |

> 결과가 기대와 다른 지점을 스스로 짚어 물으면 우수의 강한 근거.

## ⑦ 자기 해결
*측정 축: 도움(힌트)을 활용해 스스로 해결로 가는가 — 메타인지/자기조절 (CT 총점과 분리 집계)*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 직접적인 정답만 요구 | "그냥 답 알려 주세요." |
| 2점 | 힌트를 받고도 다시 정답 요청으로 회귀 | "(힌트 후) 그래서 답이 뭐예요?" |
| 3점 | 힌트를 바탕으로 자기 접근·다음 단계를 스스로 제안 | "힌트 보니 인덱스를 비교하는 거군요. 첫째·둘째부터 비교해 볼게요, 맞아요?" |

> 도움 미사용 처리: 힌트 없이 스스로 정확히 해결 = 우수에 준함. 도움이 필요해 보이는데 끝까지 요청도 없고 해결도 못 함 = 1점(도움 회피).

## (선택) ⑧ 패턴 인식 / 일반화
*측정 축: 코드/문제에서 반복되는 규칙·구조를 알아보고 일반화하는가 — 채택 시 CT 지표에 합류*

| 등급 | 기준 | 예시 발화 |
|---|---|---|
| 1점 | 개별 사례·줄만 보고 반복 규칙을 못 알아챔 | (각 부분을 무관한 것으로 따로따로 질문) |
| 2점 | 반복된다고 언급하나 규칙으로 일반화하진 못함 | "이 부분이 아까랑 비슷한 게 또 나오네요." |
| 3점 | 반복 구조·규칙을 일반화해 질문 | "입력마다 같은 처리를 반복하는 누적 패턴이죠? 다른 입력이 와도 같은 규칙이 적용되겠네요." |

## 출력 형식 (채점 결과 — 자동 처리용)

채점기는 위 루브릭으로 학생 발화를 평정한 뒤, **아래 JSON 객체 하나만** 출력한다(마크다운·설명 문장 금지).

- 각 지표 점수는 정수 `1`·`2`·`3`, 또는 관련 발화가 전혀 없으면 문자열 `"N/A"`.
- ⑦ `자기해결`은 **CT 총점과 분리**해 따로 집계한다(메타인지/자기조절 지표).
- ⑧ `패턴인식`은 채택 지표로 CT 총점에 합류한다.
- `weak_ct`는 N/A를 제외한 CT 지표 중 가장 낮은 점수의 지표명. 동점이면 학습 효과가 큰 지표를 고른다.
- 학생 발화가 전혀 없으면 모든 지표를 `"N/A"`로 한다.

```json
{
  "문제분해": 2,
  "용어사용": 3,
  "추상화": 2,
  "실행흐름": 3,
  "자료표현": "N/A",
  "동작파악": 2,
  "패턴인식": 1,
  "자기해결": 2,
  "weak_ct": "패턴인식",
  "feedback": "한국어 피드백 2~3문장"
}
```
