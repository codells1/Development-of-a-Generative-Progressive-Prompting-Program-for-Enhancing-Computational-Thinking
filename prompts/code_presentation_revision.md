# 코드 제시 생성 사양 (개정) — 의사코드 + 파이썬

> **적용 범위:** 한 세션의 *제시용 코드 자산*(파이썬 코드 + 한글 의사코드) 생성과
> 유형 구조·제시 매핑만 다룬다. 문항(MCQ) 내용 생성은 이 문서 범위 밖이며 별도로 정의한다.
>
> **이 문서는 `prompts/code_reading_generation.md`의 다음 두 부분을 대체한다.**
> 1. Stage 1(코드 생성) 규칙 — 기존의 "함수 3~5개 / 5개 구성요소" 규칙을 §3으로 교체.
> 2. 유형(ct_skill) 목록·순서 — 기존 "분해→패턴인식→추상화→알고리즘적사고→통합"을 §2로 교체.
>
> Stage 2의 문항 내용 생성 규칙(`answer_type`, `verification_snippet`, `focus_points` 등)은 **그대로 둔다.**

---

## 1. 산출물 (Artifacts)

세션 생성 시 두 자산을 만든다.

- `python_code` (string): 외부 입력 없이 그대로 실행되는 파이썬 코드. **source of truth.**
- `pseudocode_lines` (string[]): `python_code`를 한글 의사코드로 번역한 것. **단계(줄) 단위 배열.**

**기본 정책 — 하나의 알고리즘.** `python_code`를 먼저 생성·검증하고, 그것을 *번역*해
`pseudocode_lines`를 만든다. 두 자산이 같은 알고리즘이라 일관성이 자동 보장된다.
(유형1·2의 의사코드와 유형3~5의 파이썬을 서로 *다른* 알고리즘으로 분리하고 싶다면
이 정책만 바꾸면 된다 — 그 경우 python_A→의사코드_A, python_B를 따로 생성한다.)

---

## 2. 유형 구조 + 제시 매핑

문항은 5개. 순서·유형·제시 코드는 아래로 고정한다. 각 문항 객체에 `code_kind` 필드를 둔다.

| index | ct_skill        | code_kind (제시)  |
|-------|-----------------|-------------------|
| 1     | 문제분해         | pseudocode        |
| 2     | 추상화/알고리즘   | pseudocode        |
| 3     | 패턴인식         | python            |
| 4     | 코드             | python            |
| 5     | 코드             | python            |

- 프론트 코드 섹션은 **현재 문항의 `code_kind`** 에 따라 `pseudocode_lines`(줄별 렌더)
  또는 `python_code`를 표시한다.
- 같은 세션의 모든 문항은 §1의 동일 자산을 가리킨다(문항마다 코드를 새로 만들지 않는다).
- ct_skill "코드"가 4·5에서 두 번 나온다(중복 허용). 두 문항의 세부(예: 중간 출력 / 최종 출력)는
  문항 생성 단계에서 구분한다 — 이 문서 범위 밖.

## 3. 파이썬 코드 생성 규칙  (Stage: python)

**구조 (필수)**
- 함수 *정확히 1개*. 그 함수 내부에 반복문(for/while) *1개 이상*.
- 함수 호출과 `print`로 *관찰 가능한 출력* 1개 이상.
- 반복마다 값이 변하는 변수가 최소 1개(패턴인식·출력 추적 문항용).

**권장**
- 반복문 안에 조건 분기(if) 1개 — 유형2(순서도) 문항이 자명해지지 않도록.

**제약**
- 길이: 최대 20줄, 권장 10~16줄.
- 표준 파이썬만(import 금지), `input()` 금지, 데이터는 코드 안에 고정 → *결정적으로* 실행.
- 변수·함수명은 의미가 드러나게. 주석은 최소화(추적 문항의 단서가 되지 않게).

**RAG**
- `code_examples`에서 구조가 유사한 예시 2~3개를 retrieve해 *스타일·구조 앵커*로만 사용(복붙 금지).
- `code_examples`는 **전체 파일 = 1문서** 임베딩 유지(문자 단위 분할 금지). `problem_templates` 설정은 건드리지 않는다.

**출력 형식**
- LM Studio structured output(`response_format` = `json_schema`)로 `{"python_code": "..."}` 강제.
  (Qwen 계열 JSON 절단·반복 방지 — regeneration 경로 포함 **모든** LLM 호출에 적용.)
  - 기존처럼 코드블록 raw 출력을 유지하려면 코드펜스만 추출해도 되지만, json_schema 쪽이 파싱이 안정적이다.
- 생성 모델: **Qwen3.5-9B (LM Studio)**, temperature 0.6 권장.

**검증 (생성 직후, 코드로 — LLM 판단에 맡기지 말 것)**
1. `ast.parse` 성공(구문 오류 없음).
2. `ast` 상 `FunctionDef` 개수 == 1.
3. 그 함수 내부 `For` + `While` 노드 합 >= 1.
4. subprocess 실행(5초 타임아웃) → 비어있지 않은 stdout 발생.

→ 1~4 중 하나라도 실패하면 regeneration(최대 3회). 3회 실패 시 스킵 로그.

## 4. 한글 의사코드 생성 규칙  (Stage: pseudocode)

- **입력:** §3에서 생성·검증된 `python_code`.
- **작업:** 의미가 동일한 한글 의사코드로 *번역*(새 알고리즘 생성 금지).
- **출력:** `pseudocode_lines` — 각 원소가 독립적 *단계 한 줄*.
  (유형1 문제분해가 "단계 순서 맞추기"이므로 줄 단위가 핵심이다.)

**스타일 컨벤션 (예)**
- 함수 정의 → `함수 <이름>(<매개변수>) 정의:`
- for 반복 → `i를 <시작>부터 <끝>까지 반복:` · while → `<조건>인 동안 반복:`
- 조건 → `만약 <조건>이면:` / `아니면:`
- 누적·대입 → `<변수>에 <값>을 더한다`, `<변수>를 <값>으로 둔다` 등 자연어 동사
- 반환 → `<값> 반환` · 출력 → `<값> 출력`
- 블록은 들여쓰기(앞 공백 2칸)로 표현.

- **few-shot:** §6 예시 2쌍을 프롬프트에 직접 포함(별도 RAG 불필요).
- **출력 형식:** `json_schema`로 `{"pseudocode_lines": ["...", "..."]}` 강제.
- **검증(가벼움):** 줄 수 >= 3, 한글 컨벤션 키워드(반복/만약/반환/출력 등) 사용,
  파이썬의 제어구조(반복·조건)가 의사코드에도 등장하는지 확인.

---

## 5. 생성 순서

- 권장: `python_code` 생성·검증 → `pseudocode_lines` 파생.
- 의사코드가 파이썬에서 파생되는 *의존 관계*만 유지하면 되고, 그 외 파이프라인 배치 순서는 자유.

## 6. few-shot 예시 (의사코드 번역)

**예시 A**

파이썬:
```python
def 누적합(n):
    합 = 0
    for i in range(1, n + 1):
        합 += i
    return 합

print(누적합(5))
```
pseudocode_lines:
```
함수 누적합(n) 정의:
  합을 0으로 둔다
  i를 1부터 n까지 반복:
    합에 i를 더한다
  합 반환
누적합(5)의 결과를 출력
```

**예시 B**

파이썬:
```python
def 짝수개수(목록):
    개수 = 0
    for x in 목록:
        if x % 2 == 0:
            개수 += 1
    return 개수

print(짝수개수([3, 8, 5, 12, 7]))
```
pseudocode_lines:
```
함수 짝수개수(목록) 정의:
  개수를 0으로 둔다
  목록의 각 원소 x에 대해 반복:
    만약 x가 짝수이면:
      개수에 1을 더한다
  개수 반환
짝수개수([3, 8, 5, 12, 7])의 결과를 출력
```

## 7. 데이터 형태 (생성 산출물 = 문항 생성 입력)

```json
{
  "python_code": "def ...\n    for ...",
  "pseudocode_lines": ["함수 ... 정의:", "  ...", "..."],
  "code_meta": { "func_name": "...", "loop_kind": "for", "n_lines": 12, "has_conditional": true }
}
```

문항(MCQ) 생성 단계는 이 객체 + §2 유형 구조를 입력으로 받는다(추후 정의).
